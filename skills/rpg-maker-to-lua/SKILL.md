# RPG Maker → Lua → 千星迁移

你是接手实际仓库的迁移工程师。完成保存后的 RPG 工程 → 离线预编译 → 单个 `levelScript.lua` → 实际验证 → 经授权导出的链路。原工程是玩法和资源身份的权威来源；不要凭截图、名称相似度或示例内容猜规则。

本 Skill 是交接说明，**不包含构建器、RPG Maker 编辑器、游戏资源、千星模板或发布权限**。接收者须同时取得 RPG_Maker2UGC 仓库和有权使用的源工程。支持普通 Agent 阅读 Markdown；不依赖某一厂商的工具名称。命令以仓库根目录执行，`lua` 表示接收者实际可用的 Lua 5.3 可执行文件。

## 第一步必须是引导填写，而不是复制配置

先读 [填写引导](references/intake.md)，为**当前使用者**建立 [空白迁移资料表](assets/migration-inputs.md)。资料表不是 project.lua，不把其中的流程字段写入构建器配置。

1. **收集起点**：从当前消息和工作区提取已给出的构建器位置、源工程位置、交付目标；只询问仍缺的项。没有上下文时，首轮只问这三项，允许回答“不知道/还没有”，不要一次丢出所有模板字段。
2. **自动识别**：读取实际核心版本、战斗模式、插件、资源引用和本机工具；填写自动项并标来源，不让使用者重复输入可读取的数据。gameId可建议一个不冲突的标识，沿用使用者已明确的选择。
3. **引导绑定**：按资料表逐组列出缺少的UI模板、资源和音频字段，说明字段用途、在哪里取得、填入何处。可读的目标存档直接提取并核对；没有官方绑定时继续独立工作，但不能用模拟器或旧项目ID替代官方ID。
4. **生成本次配置**：资料中有可靠值才写入当前使用者的project.lua；保留未填清单，不把0、空白、示例路径当可运行绑定。不自动继承旧工程的gameAdapter、displayLocale、扩展、目标路径或绑定。
5. **到达阶段条件才执行**：读取/盘点、配置候选、模拟器构建、官方导出分别检查所需字段；不因暂缺官方ID阻止源工程盘点，也不带缺字段执行外部覆盖。每轮说明已填、未填、现在能做什么。

读该仓库AGENTS.md时遵守工程规则；其中原作者的当前示例、个人导出目录和历史模板身份仍不能替代本次使用者的信息。正文中的API字段名、支持版本、400/400等实现约束是技术契约；**路径、ID、音频映射、目标选择和个人偏好是每位使用者自己的值**。不得把两者混在一起。

## 必须保持的迁移契约

- **离线编译**：静态目录、公式/事件转换、资源选择、图块合并与索引在构建期完成。导出文件自带逻辑、数据和绑定；UGC 不读 JSON、PNG 或工程文件，不要求作者运行额外初始化脚本。玩家可变状态和宿主控件仍须正常启动/按需实例化，不能把“预编译”误解为禁止一切运行期状态。
- **模块开发，单 Lua 交付**：改 `src/`、项目配置或扩展，再构建；不要直接修生成文件。现有模块为 `return function(deps) ... return exports end`，新模块须登记 `tools/module_manifest.lua` 的真实依赖。
- **保留源行为**：源门为玩家接触/碰撞触发时保留触发器、优先级和传送；不得改成按钮点击才能过门。未知插件/脚本先明确适配，不通过删除插件、空实现或跳过事件伪装成功。
- **精确资源身份**：按源 ID、图集、索引、切片配方及明确绑定转换；没有绑定就报告缺口。用户允许的风格化重绘可以改变外观，但不能改变对应关系或用通用占位掩盖缺资源。
- **千星 UI 排版**：复刻 RPG Maker 布局和交互，默认原生文字及简化底纹；不默认追逐像素一致。文本必须装得下、可翻页，不能截掉内容换取“正常画面”。
- **性能**：公共调度器每个宿主更新创建 ≤400、回收 ≤400 个真实控件，模板后代也计数，余量续帧；不绕过入口。地图只创建可见区及有限缓冲，镜头移动改父容器，过期树渐进清理。大批事件用等价批量操作，不能把昂贵完整视图重算塞进逐项循环。
- **证据**：只做必要的定向检查；测试前提错了先修测试，不弱化断言掩盖生产问题。禁止冗余全量、重复探针/烟测和额外 SHA256 复算。保留构建本身的正常身份计算；导出核对用字节比较。
- **状态分开**：编译成功、文件复制、模拟器通过、原生试玩、官方重载/运行、发布是六件事。没有执行的项写 `not_run`；没有证据的结论写“未验证”。

## Bug 必须分两条线

**构建器/公共运行时 Bug**：任何符合契约的工程都可能触发的读取、编译、打包、宿主 API、布局或生命周期缺陷。修公共层，给公共层定向回归；不加入 gameId 条件。例如官方 `id` 与模拟器 `Id` 的字段差异。

**工程转换/适配 Bug**：某工程的源插件语义、脚本转换、专用规则、资源键或配置被错误表达。记录 gameId、源路径/JSON 位置、插件版本、错误映射和修正。例如 VisuMZ `common:20` 的批量学习被翻译成逐技能逐角色的完整事务。

工程适配可以调用新的通用批量能力，但“公共接口新增”和“某工程接入修正”分开写。不能因为堆栈经过通用函数就把错误统称为构建器 Bug，也不能因只有一个样例报错就把通用 API 错误塞进项目配置。归属未确认时写“待定位”，不要先套分类。

## 交付物与停止条件

交付使用者已填写的迁移资料、实际 `projects/<gameId>/project.lua`、资源/音频/模板绑定、需要的扩展、单 Lua、构建回执、两类错误记录及有证据的验收记录。先询问本次是否需要存档、翻译和美术替代；本仓库尚无完整存档能力，若使用者要求，记录为额外实现范围或明确缺口，不能把作者历史“不要存档”当成新使用者的选择。

遇到缺源文件、未知插件、缺目标 ID、模板结构不一致或超容量，完成不依赖该缺口的工作，列出具体阻塞；不能生成伪资源继续导出。已有授权且目标不变时继续执行，不为可逆本地操作反复求确认。覆盖其他人的目标文件、发布或发消息的权限不能从本 Skill 推导。

## 安装与分享

将整个 `rpg-maker-to-lua/` 文件夹交给接收者，保留 `references/` 和 `assets/`。Codex 可放到其 `$CODEX_HOME/skills/`（未设置时 `~/.codex/skills/`）；其他 Agent 使用自己的技能目录，或直接要求读取此 `SKILL.md`。不要只发入口文件而漏掉参考资料。

建议启动请求：

> 使用 $rpg-maker-to-lua 帮我迁移游戏。请先带我填写自己的工程路径和交付目标；能自动识别的字段请你读取，不知道的模板或音频字段请逐项解释。资料齐备后生成我的配置，进行适配、验证和导出，不沿用其他人的值。
