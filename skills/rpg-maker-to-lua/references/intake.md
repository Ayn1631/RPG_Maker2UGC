# 引导使用者填写自己的迁移信息

## 工作方式

不要开始就复制某个示例project.lua。先以 [空白资料表](../assets/migration-inputs.md) 为结构，记录当前使用者提供和Agent实际发现的信息。使用者可以在对话中回答，Agent代填；也可直接编辑资料表。已填写的值不重复问，只解释尚缺项。

资料表中的空格表示“未提供”，不是0、false或默认沿用。Agent发现的值附文件/界面来源及状态：`已提供`、`已读取`、`已核对`、`待提供`或`不适用`。不要把猜测升级为已读取。表中流程字段不是CLI配置字段。

gameId及工程位置确定后，把资料表保存到本次 `projects/<gameId>/migration-inputs.md`；已有资料表先核对工程/目标身份，仅修改本次相关字段，保留使用者内容。目标或使用者变更时建立新档案，不能悄悄复用上一次绑定。写入技能目录的空白模板应始终保持空白。

## 第一轮：只收集能开始的三项

若消息/上下文尚无这些信息，可使用这段开场：

> 先告诉我三件事，已有的信息我会自动读取：
> 1. 你的RPG Maker工程在哪个文件夹？不知道根目录时给外层文件夹即可。
> 2. RPG_Maker2UGC构建器在哪？如果当前工作区就是构建器，可直接说“当前工作区”；还没有也可以说明。
> 3. 这次先做到哪一步：模拟器试玩、导出Lua文件，还是官方UGC试玩？

一次只问缺失项，不机械地把模板原文发给所有人。使用者只给源目录时，可以发现当前仓库再问交付目标；只有外层目录时，在授权目录内定位真实game子目录。找不到构建器时询问其包/仓库来源，不编造下载地址。官方试玩缺环境时仍可先完成模拟器阶段，但明确这是阶段目标，不把回答改成“只需要模拟器”。

## 第二轮：Agent读取，使用者只决定偏好

Agent确认OS/shell、Lua5.3路径及所需依赖；读取核心版本、System战斗模式、静态插件列表、实际源资源，代填这些自动项。

gameId可以由源名称建议成合法英文标识，并检查目录冲突；使用者已给标识就遵循。project.lua路径取已有文件或init回执的实际output；禁止假设候选已替代旧配置。

以下偏好若影响当前实施才追问，能直接延续本次使用者已表达的选择就不问：

- 美术：保留源图经目标模板接入，还是允许图元重绘？允许替代的范围是什么？
- 语言：保留源文本还是翻译？翻译哪种语言？不能自动套用Visu的zh-CN专用配置。
- 存档：本次是否必需？当前实现不完整，必需时列为新范围/缺口，不默认为作者之前的“排除”。
- 源工程：保持只读，还是明确允许在副本中调整？普通迁移无需反复审批只读和可逆的配置生成。

## 第三轮：按目标分开收集绑定

先判断使用者是否有自己的模拟器存档、官方模板导出/目录或现有绑定配置。有文件和工具即可读取；用户不应被要求重新抄一遍已经可以读出的全部ID。对读出的配置，核对它属于**哪个目标工程**，不能以“文件里有数字”证明可在另一个目标使用。

UI字段逐项解释：

| 向使用者说明 | 写入的配置位置 | 从哪里取得 |
| --- | --- | --- |
| 可克隆的空容器模板 | worldPreview.containerTemplate | 当前目标客户端控件模板列表中的模板索引 |
| 显示文字的文本框模板 | worldPreview.textTemplate | 同一目标的文本框模板索引；同时核对字号下限 |
| 接收点击的按钮模板 | worldPreview.buttonTemplate | 同一目标按钮模板索引 |
| 承载图元/图片的模板 | worldPreview.imageTemplate | 同一目标图片控件模板索引 |
| 窗口交互/光标模板 | worldPreview.cursorTemplate | 目标中实际受支持的交互控件模板 |
| 绘制实色图元的图片资源 | worldPreview.whiteImageId | 目标资源目录中的图片ID，不是模板索引 |
| 头像与图标容器 | worldPreview.artTemplates.portrait / icon | 当前目标的对应模板；具体源头像/图标还需明确映射 |
| 模板的根与内置后代结构 | uiTemplateCatalog | 从同目标的实际模板存档导入，不能凭数量猜 |

没有模板时，说明需创建的类型和用途，并在用户已授权且有工具时协助创建；工具不支持则让使用者提供实际ID。不得填写原作者的107374…编号，不得用0通过检查。模拟器可以选随附模板，但须明确其适用范围并核对该存档；这些值不自动成为官方绑定。

音频分开询问：

1. Agent从源工程列出实际使用的BGM/BGS/ME/SE名称，生成空映射行；不用使用者手工枚举源声音。
2. 询问目标是否已有接收端，以及使用哪些信号名/索引。默认信号名仅可作为明确建议，不能假装接收端已部署。
3. SE选择客户端播放还是信号接收端播放。客户端需要真实audioId，信号路径需要真实index；可读的资源目录由Agent按desc找候选并记录替代关系，不随意分配资源编号。
4. UI光标/确认/取消/错误反馈若有独立要求，逐项绑定cursor/ok/cancel/buzzer。无ID时保持缺口，不拿RPG源文件名当千星audioId。

资源映射由Agent按源引用生成清单，使用者主要提供目标模板/素材来源、重绘授权和已确认替代。每条绑定可追溯到源键与目标档案；不同游戏即使同名图片也不自动共用。

## 第四轮：只在导出阶段收集目标路径

仅模拟器任务不需要官方账号、关卡号或外部Lua目录。需要文件导出时，询问**完整目标Lua文件路径或其父目录**，不要要求输入账号密码/凭据；给完整路径即可确定位置。核对是否只允许一个Lua文件、目标是否已有文件、该文件是否属于本次工程及已有覆盖授权。

不要拼接技能作者的BeyondLocal账号/关卡号。UGC模板接入与文件导出分别核对，导出路径存在不代表其中模板已配置。

错误记录目录从本次工作区约定取得；无约定时建议放当前工程文档目录并标明建议，不沿用作者个人StarGame目录。路径带下划线按普通字符处理。

## 分阶段条件

| 工作 | 需要什么 | 缺少时仍能做什么 |
| --- | --- | --- |
| 读取/盘点 | 可读源目录；代码核对还需构建器目录 | 不创建假源文件；先定位目录/工具 |
| init配置候选 | 源、仓库、Lua/LFS、gameId | 缺模板仍可生成候选，但保持不可构建状态 |
| inspect/资源导出/build | 合法配置、匹配的目标基础绑定、支持的插件/事件；build另需完整资源/音频与模板目录 | 继续源分析、适配和清单编排，不临时删插件或抄ID |
| 模拟器试玩 | 已成功构建的同目标Lua、真实存档及工具 | 可交付代码/产物，但标可视化not_run |
| 官方导出/试玩 | 本次指定输出路径及相应权限；官方运行还需该目标模板、接收端和可操作环境 | 不触碰旧个人目录、不拿模拟器ID当官方绑定 |

字段未齐时按“已填/缺少/正在做”简述。例如：已识别MZ及版本；缺文字与容器模板ID；先整理源插件和资源映射，暂不进行目标构建。不要为所有字段安排总确认门槛，只在真正缺信息或授权的步骤等待。

## 从资料表生成命令与配置

后续文档的PowerShell变量全部由Agent从**本次资料表已读取/提供的值**绑定后使用：

| 命令变量 | 资料来源 |
| --- | --- |
| $R2uRepoRoot / $R2uSourceRoot | 构建器根 / 本次源游戏根 |
| $R2uLuaExe / $R2uPythonExe | 实际工具可执行文件；后者仅相关工具需要 |
| $R2uGameId / $R2uProjectFile | 本次标识 / 实际配置文件路径 |
| $R2uBindingsProjectFile | 明确属于同目标的可复用配置；没有则不传--bindings |
| $R2uSimulatorFile | 本次目标模拟器存档 |
| $R2uTemplateCatalogFile | 要生成的同目标模板目录路径 |
| $R2uTileBindingsFile / $R2uCharacterBindingsFile | 实际完成的图块/人物清单；不用就省略对应参数 |
| $R2uTargetLua / $R2uTargetDirectory | 使用者指定的输出文件 / 父目录 |
| $R2uEvidenceFile / $R2uEvidenceTarget | 真实证据清单 / 本次simulator或ugc目标 |

这些是命令示意变量，不是Skill预设的值，也不是新的project.lua字段。变量缺失/空白时不要执行对应命令。在其他shell中使用等价的参数传递与路径引用，不能把PowerShell符号直接当路径。对可选功能，只写确有输入且当前版本支持的配置字段；未知gameAdapter、语言专用开关或不存在的图元库路径应省略，而不是填入旧示例值。
